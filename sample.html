最小サンプル：評価を伏せて比較する手順

完全に架空の会話と手書きの評価を使う、ローカルの手順デモです。Codex、Claude、その他の実LLMは呼び出しません。実際の独立QAや、製品品質の実証結果ではありません。 このサンプルの実行・テストを技術実証レポートの累計へ加算しません。

「Codex役の事前評価を固定する」「モデル名と先行評価を伏せた入力を別評価者へ渡す」「戻ってきた評価を同じ観点で比べる」という考え方を、Node.jsだけで追えます。開発リポジトリの製品コード・監査生ログ・顧客データは使用していません。

依存と実行

Node.js 20以降を使用します。標準ライブラリのみで、npm install、APIキー、ネット接続は不要です。

リポジトリのルートで実行します。

node examples/blind-qa/demo.mjs
node --test examples/blind-qa/workflow.test.mjs

サンプルのフォルダを作業場所にした場合は、node demo.mjs と node --test workflow.test.mjs です。

デモは既存の出力を上書きせず、output/run-<ランダムID>/ に1実行分を保存します。生成物はこのフォルダの .gitignore で除外します。外部APIへの通信処理はありません。終了後に常駐するサーバーもありません。

処理の順序と出力

  1. fixtures.mjs の架空データを読み、Codex役の手書き評価をJSONへ固定します。保存したUTF-8文字列のSHA-256を実行中のメモリに保持します。
  2. 事前評価の固定後に、別評価者向け reviewer/blind-input.json を作ります。会話は caseId / turn / input / response だけを階層ごとに選び、採点基準と一緒に渡します。モデル名、元の識別子、メタデータ、先行評価はコピーしません。
  3. このデモでは、実評価者の代わりに、あらかじめ手書きした別評価を reviewer/second-review.json として読み込みます。
  4. 保存した事前評価とブラインド入力を読み直し、保持したハッシュと照合します。不一致なら比較を止めます。単なる整形変更でもバイト列が変わるため不一致になります。
  5. ケースと観点を対応させて、判定・重要度・理由を comparison.json へ並べます。manifest.json には手順と3ファイルのハッシュを保存します。
output/run-<ID>/
  custodian/first-review.json     Codex役の先行評価（別評価者へ渡さない）
  reviewer/blind-input.json       別評価者へ渡す入力
  reviewer/second-review.json     手書きの架空評価
  comparison.json                同じケース・観点での比較
  manifest.json                  ハッシュと実施順の記録

実際の運用で別評価者へ渡す対象は blind-input.json だけです。出力フォルダ全体や fixtures.mjs を渡すと先行評価が見えます。このローカルデモは同じプロセスで両方の評価を扱うため、評価者の隔離や独立性を保証しません。

架空例で確認できること

読書会の案内と友人へのお礼という2ケースを、条件維持と文章の使いやすさの2観点で比較します。架空ケース2には「約束を加えない」という入力に反して、食事をごちそうする約束が含まれています。

Codex役の評価は条件違反をLowとし、文章の使いやすさはPASS。別評価者役は条件違反をMediumとし、そのまま使える文章でもないと評価します。出力は 4行中2行の判定または重要度に差があることを示します。同じ問題の異なる見方なので「不具合を2件発見した」や、重大度の合計へは変換しません。修正候補は表示しますが、実際の修正・再評価・採用判断は行いません。

テストと再現範囲

node:test は以下を検証します。

  • 未知の項目を各階層へ追加しても、モデル名・元ID・先行評価がブラインド入力へ入らないこと。
  • 保存後の事前評価や会話を変更した場合に、比較を拒否すること。
  • 事前固定より前の入力作成、評価の再固定、二重比較を拒否すること。
  • 別評価の並び順が異なっても、同じケース・観点に対応させて差を示すこと。
  • 未評価の観点や重複を、暗黙に無視せずエラーにすること。

固定データと評価のJSON内容・ハッシュ・比較結果は同じ条件で再現できます。実行ごとに出力フォルダ名だけ変わります。テスト内で異常条件も与えますが、モデルを動かす評価ではありません。

未再現の範囲と限界

  • 実LLMへの呼び出し、評価能力、盲検の効果、人間の使いやすさ、統計的優位、開発時の実監査の再現は含みません。
  • 許可項目方式が除くのは構造化メタデータです。会話本文自身にモデル名・先行所見・個人情報が書かれていれば、その文字は残ります。実データを使う場合は配布前の本文確認と編集が必要です。
  • ハッシュは、この実行で保持した値からの変更を検出します。原本とハッシュを両方差し替えられる人への防御、外部タイムスタンプ、署名、実行順の第三者証明にはなりません。
  • 別評価者役の値は正解ではありません。差があっても、どちらが正しいかを自動決定しません。現実の運用では担当者が根拠を確認し、必要な修正・再評価を判断します。
